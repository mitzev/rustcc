# rustcc v1.13.7 — Rust subclasses an imported C++ class (with virtual destructor)

**A fork-rustc release.** v1.13.7 lets a Rust `class Derived : CppBase`
inherit from an **imported** C++ polymorphic class — the one direction
of inheritance that was previously unsupported — with full
cross-boundary virtual dispatch **and a working virtual destructor**.
This unlocks the canonical FLTK custom-widget pattern: a Rust type that
overrides `handle()` / `draw()` and is owned (and `delete`d) by C++.

The fork rustc patches changed, so the prebuilt toolchain tarballs are
new; the rust-analyzer plugin is rebuilt from the same tag.

## What ships

### A. Subclass an imported C++ class

```rust
// CppBase is generated by cxx_importer from a C++ header.
pub class MyWidget : CppBase {
    extra: i32,
    pub constructor fn new(x: i32, extra: i32) -> Self {
        MyWidget { __base: CppBase::new(x), extra }
    }
    pub override fn foo(&self) -> i32 { self.extra + 100 }       // concrete base virtual
    pub override fn describe(&self) -> i32 { self.extra + 200 }  // PURE base virtual
    pub virtual fn only_mine(&self) -> i32 { self.extra * 3 }    // brand-new virtual
}
```

C++ dispatching `foo()` / `describe()` through a `CppBase*` that points
at a `MyWidget` lands in the Rust `override` — exactly as C++-native
virtual dispatch would. Both **concrete** and **pure** base virtuals are
overridable.

### B. Cross-boundary virtual destructor

When the imported base has a virtual destructor, `delete (CppBase*)w`
from C++ runs the Rust `Drop`, destroys the base subobject (its `Drop`
runs the C++ base destructor), and frees — **each exactly once** (no
leak, no double-free; verified with balanced ctor/dtor counters).

Ownership model: C++ owns and `delete`s the object (the FLTK model), so
the Rust factory allocates it through the C++ allocator (`operator new`
+ placement-construct); the vtable's deleting destructor reclaims it
with `operator delete`.

### How it works (compiler + importer)

- **New attribute `#[rustc_cxx_imported_vtable = "<spec>"]`** —
  `cxx_importer` places it on the imported base's `#[repr(C)]` struct,
  listing the base's primary-vtable function-pointer slots in C++ order
  (`zti=…;[vdtor=1;]slot=<name>,<symbol>;…`). Pure virtuals carry
  `__cxa_pure_virtual`; `vdtor=1` flags a virtual destructor.
- **Chain-walk** (`rustc_symbol_mangling::itanium`) seeds the derived
  vtable from those slots; a Rust `override fn` matched by name takes
  over a slot, a non-overridden slot points directly at the real C++
  symbol. The derived shares the base vptr at offset 0; `_ZTI<Derived>`
  chains to the external base `_ZTI`. The imported base never emits its
  own `_ZTV`/`_ZTI`/`_ZTS` (C++ owns them).
- **Virtual destructor codegen** — the derived vtable's leading dtor
  slots run the full Rust drop glue (`drop_in_place::<Derived>`, which
  drops every field including the `__base` subobject). The mono
  collector now collects that drop glue for such classes (its vtable
  reference is invisible to lazy collection). The importer's base `Drop`
  calls the base-object destructor (`D2`), subobject-safe.
- **Targets** — Itanium (Linux/macOS, ARM + Intel) and MSVC (single
  scalar-deleting destructor `??_G` in the vftable's leading dtor slot).

### Tooling

- **rust-analyzer / VS Code**: no change required — the existing
  `class … : Base` inheritance support covers subclassing an imported
  base, and the virtual destructor is plain `impl Drop`. The plugin is
  rebuilt from this tag.

## Examples

- **`examples/subclass_cpp_base/`** — end-to-end: `cxx_importer`
  generates the `CppBase` binding from a C++ header, the fork rustc
  compiles `class MyWidget : CppBase`, and C++ dispatches through a
  `CppBase*` into the Rust overrides; `delete` runs the Rust `Drop`.

## Verification

- ARM (`aarch64-apple-darwin`, host) and Intel (`x86_64-apple-darwin`,
  cross-compiled + run under Rosetta): pass.
- All fork `class`/virtual probes (`./fork/tests/run.sh`) and the
  Rust-Rust `examples/virtual_override` round-trip: no regressions.
- `cargo test -p cxx_importer --features build`: pass, incl. new
  `tests/imported_vtable.rs`.

## Limitations

- Single inheritance, no virtual bases (the importer already rejects
  virtual inheritance).
- The MSVC scalar-deleting destructor always frees (matching the fork's
  existing v1 MSVC posture); correct for the `delete`-through-base
  ownership model this feature targets.
- The base-name must match the C++ class name (global namespace) for the
  RTTI symbol to line up; the importer emits the exact `_ZTI` via the
  attribute's `zti=` record.
